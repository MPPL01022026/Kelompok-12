# Lessons Learned

Tahap 5 - Project Closure | Kelompok 12  
Disusun dari kejadian nyata selama proyek.

## 1. Yang Berjalan Baik

| No | Hal | Dampak |
|---|---|---|
| 1 | Pembagian tugas memakai kode WBS dan penanggung jawab jelas | Tiap anggota tahu bagiannya, dokumen tersusun konsisten |
| 2 | Wawancara langsung dengan Kak Linda sejak 30 September 2026 | Masalah utama (pesanan lupa) jelas sejak awal dan menjadi arah prototipe |
| 3 | Rancangan dibuat sangat sederhana karena pengguna belum memahami aplikasi | Prototipe fokus pada hal yang dibutuhkan, yaitu mencatat pesanan |
| 4 | Pengujian dilakukan terhadap logika dan tampilan | Dua kekurangan ditemukan dan diperbaiki sebelum penyerahan |
| 5 | Repositori GitHub dipakai bersama oleh empat anggota | Riwayat kerja tercatat dan bisa diperiksa |

## 2. Yang Kurang Baik dan Penyebabnya

| No | Masalah | Penyebab | Dampak |
|---|---|---|---|
| 1 | Tenggat resmi baru dipastikan setelah jadwal pertama dibuat | Tenggat tidak ditanyakan di awal | Jadwal disusun ulang dan cadangan waktu menipis |
| 2 | Waktu, manday, dan biaya aktual tidak dicatat selama pelaksanaan | Tidak ada kebiasaan mencatat harian | Perbandingan rencana dan realisasi di Tahap 4 hanya bisa sebagian |
| 3 | Data wawancara awal kurang (harga tepat, penjualan per produk, internet) | Daftar pertanyaan belum disiapkan sejak awal | Sebagian kebutuhan memakai perkiraan |
| 4 | Prototipe belum divalidasi Kak Linda | Kak Linda belum memahami aplikasi dan jadwal bertemu terbatas | Keberhasilan K2 sampai K4 belum terbukti |
| 5 | Unggahan awal ke GitHub berupa folder bersarang dan file ganda | Struktur repositori tidak disepakati dan unggahan dilakukan per file | Halaman depan repositori sempat tidak sesuai, perlu perapian |
| 6 | Data realisasi yang sempat dikumpulkan belum cocok dengan bukti di repositori | Tidak ada catatan harian sebagai acuan | Data tidak dipakai agar laporan konsisten |

## 3. Rekomendasi untuk Proyek Berikutnya

| No | Rekomendasi |
|---|---|
| 1 | Tanyakan tenggat resmi semua tahap di awal, lalu susun jadwal dari tenggat itu |
| 2 | Catat realisasi tiap hari kerja: tanggal selesai, jam kerja tiap orang, dan pengeluaran. Satu baris per hari sudah cukup |
| 3 | Siapkan daftar pertanyaan wawancara sebelum bertemu dan catat jawabannya langsung |
| 4 | Tunjukkan prototipe sederhana ke pengguna sedini mungkin, jangan menunggu produk lengkap |
| 5 | Sepakati struktur folder repositori di awal dan gunakan branch serta Pull Request |
| 6 | Isi data realisasi hanya dari catatan atau bukti, bukan dari ingatan |
